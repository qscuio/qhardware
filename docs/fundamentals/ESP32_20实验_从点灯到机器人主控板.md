# ESP32 20 个实验：从点灯到机器人主控板

> 目标：不要把 ESP32 当成“开发板玩具”，而是把它当作硬件世界的实验核心。  
> 整条路线：**电 → 信号 → 数字接口 → 传感器 → 电机 → 反馈控制 → 无线通信 → 分布式系统 → PCB**

---

# 第一阶段：电和信号

前 5 个实验非常重要。

不要嫌它们简单，因为后面的 SPI、无线、电机，本质上最终都落到：

> **电压如何随时间变化。**

---

## 实验 1：GPIO + LED + 按键

先搭最简单的 LED：

```text
ESP32 GPIO
    │
   330Ω
    │
   LED
    │
   GND
```

然后接按键：

```text
3.3V
 │
按键
 │
GPIO
 │
10kΩ
 │
GND
```

重点理解：

```text
GPIO 输出 HIGH
≈ 3.3V

GPIO 输出 LOW
≈ 0V
```

同时理解：

- 输入脚为什么不能悬空
- 什么是 Floating
- 什么是上拉
- 什么是下拉

可以故意把 10kΩ 去掉，观察 GPIO 输入不稳定的现象。

---

## 实验 2：PWM

让 ESP32 输出：

```text
频率：1 kHz
占空比：50%
```

示波器应看到类似：

```text
3.3V ┌──┐  ┌──┐
     │  │  │  │
0V ──┘  └──┘  └──
```

然后分别改变：

```text
频率：
100 Hz
1 kHz
10 kHz
100 kHz
```

以及：

```text
占空比：
10%
25%
50%
75%
90%
```

要真正区分：

- **频率**
- **周期**
- **占空比**

它们不是一回事。

### PWM 平均电压

对于 3.3V PWM，50% 占空比：

\[
V_{avg}=3.3V\times0.5=1.65V
\]

于是会出现一个非常有意思的现象：

- 示波器看到的是 0V / 3.3V 快速切换
- 万用表可能显示约 1.65V

这能帮助理解“瞬时值”和“平均值”的区别。

---

## 实验 3：PWM → RC 低通滤波

电路：

```text
ESP32 PWM ── R ─────── 输出
                │
                C
                │
               GND
```

例如：

```text
R = 10kΩ
C = 1µF
```

截止频率：

\[
f_c=\frac{1}{2\pi RC}
\]

代入后：

\[
f_c\approx15.9Hz
\]

如果 PWM 是：

```text
10 kHz
```

那么经过低通滤波后：

```text
方波
 ↓
 ↓
 ↓
接近稳定的模拟电压
```

理论平均输出：

```text
10% → 约 0.33V
50% → 约 1.65V
90% → 约 2.97V
```

这个实验把以下概念真正串起来：

> **数字 PWM → RC 滤波 → 模拟电压**

也就是数字电路和模拟电路之间的桥梁。

---

## 实验 4：ADC

接一个电位器：

```text
3.3V
 │
┌───────┐
│ 电位器 │
└───┬───┘
    │
   ADC
    │
  ESP32

另一端 → GND
```

旋转电位器：

```text
0V
 ↓
1V
 ↓
2V
 ↓
3.3V
```

ESP32 ADC 把电压转换成数字。

如果 ADC 是 12 bit：

\[
2^{12}=4096
\]

理想数字范围：

```text
0 ~ 4095
```

核心模型：

```text
真实世界电压
      ↓
     ADC
      ↓
数字整数
```

这是后面所有模拟传感器的基础。

---

## 实验 5：自己做“信号发生器”

让 ESP32 输出不同频率：

```text
100 Hz
1 kHz
10 kHz
100 kHz
```

用示波器观察。

进一步可以产生：

- 方波
- PWM
- 三角波
- 扫频信号

目的不是取代专业信号发生器，而是理解：

> MCU 到底是怎么“产生波形”的？

可以比较两种方法：

### 软件翻转 GPIO

```text
GPIO Toggle
```

### 硬件 PWM 外设

```text
Hardware PWM
```

观察两者稳定性和抖动差异。

这会自然引出：

> **实时系统**

# 第二阶段：数字通信

之后重点进入：

- UART

- SPI

以后再看 PCB 原理图时，这些就不再只是名字。

---

## 实验 6：UART

推荐用两块 ESP32：

```text
ESP32 A        ESP32 B

TX ─────────── RX
RX ─────────── TX
GND ───────── GND
```

发送：

```text
0x55
```

0x55 的二进制是：

```text
01010101
```

很适合用逻辑分析仪观察。

UART 帧大致：

```text
Idle
 ↓
Start
 ↓
Data Bits
 ↓
Stop
```

可以故意设置错误波特率：

```text
发送端：115200
接收端：9600
```

观察乱码。

这样可以直观理解：

> 为什么通信双方的波特率必须一致。

---

## 实验 7：I²C

可以买一个 MPU6050、BME280、OLED 等 I²C 设备。

例如 MPU6050：

```text
ESP32             MPU6050

3.3V ─────────── VCC
GND  ─────────── GND
SDA  ─────────── SDA
SCL  ─────────── SCL
```

用逻辑分析仪抓总线。

重点观察：

```text
START

设备地址

R/W

ACK

Register Address

Data

STOP
```

代码例如：

```cpp
Wire.beginTransmission(0x68);
Wire.write(0x75);
Wire.endTransmission();
```

真正抓过一次总线后，就能把代码和线上实际波形对应起来。

---

## 实验 8：SPI

可以连接：

- OLED
- TFT 屏
- SD 卡
- SPI Flash

主要信号：

```text
SCLK
MOSI
MISO
CS
```

### I²C

```text
共享 SDA / SCL
靠地址区分设备
```

特点：

- 线少
- 多设备方便
- 通常速度不如 SPI 高

### SPI

```text
共享 CLK / Data
每个设备通常单独使用 CS
```

特点：

- 线较多
- 速度通常更高
- 协议简单直接

# 第三阶段：实时系统

---

## 实验 9：中断

不要只会轮询：

```cpp
while (1) {
    if (button) {
        ...
    }
}
```

尝试 GPIO 中断：

```text
硬件事件
   ↓
CPU 响应
   ↓
ISR
   ↓
返回原任务
```

可以做一个非常经典的实验：

```text
GPIO A 输入
     ↓
触发中断
     ↓
ISR 中把 GPIO B 拉高
```

示波器同时观察：

```text
CH1：输入信号
CH2：响应信号
```

测量：

> **Interrupt Latency**

也就是中断响应延迟。

---

## 实验 10：FreeRTOS

ESP32 很适合学习 FreeRTOS。

例如设计三个任务：

```text
Task 1
每 10ms 读传感器

Task 2
每 20ms 控制电机

Task 3
每 1000ms 上传 Wi-Fi
```

结构：

```text
             FreeRTOS
                │
     ┌──────────┼──────────┐
     │          │          │
  Sensor      Control     Network
   Task         Task        Task
```

重点学习：

- Task
- Queue
- Semaphore
- Mutex
- Timer

从这里开始，你不再只是：

> 写一个程序

而是开始：

> **设计一个嵌入式系统。**

# 第四阶段：控制真实世界

---

## 实验 11：舵机

如果使用 MG90S 等舵机，不要直接让多个舵机吃 ESP32 开发板的 5V。

推荐：

```text
直流电源
5V
 │
 ├──────── Servo V+
 │
 └──────── Servo V+

GND ─────── Servo GND
 │
 └──────── ESP32 GND

ESP32 GPIO ───── Servo Signal
```

核心要求：

> **ESP32 和外部舵机电源必须共地。**

舵机控制脉冲通常类似：

```text
周期 ≈ 20 ms

脉宽：

1 ms   → 一侧
1.5 ms → 中间
2 ms   → 另一侧
```

用示波器观察，非常直观。

---

## 实验 12：MOSFET 控直流电机

ESP32 GPIO 不能直接驱动电机。

基本结构：

```text
电源
 │
Motor
 │
MOSFET
 │
GND
```

ESP32：

```text
GPIO
 │
Gate
```

还需要：

```text
续流二极管
```

因为电机属于：

> **电感负载**

断电瞬间存在：

\[
V=L\frac{di}{dt}
\]

可能产生高电压尖峰。

这个实验能真正理解 MOSFET 为什么是功率控制中的核心器件。

---

## 实验 13：H 桥

H 桥可以实现：

- 正转
- 反转
- 刹车
- 滑行
- PWM 调速

概念结构：

```text
          Motor
       ┌────┴────┐
       │         │
       Q1        Q2
       │         │
       ├──Motor──┤
       │         │
       Q3        Q4
       │         │
      GND       GND
```

这里可以真正理解：

> MCU 并不是“提供电机能量”，而是在控制一个更大的能源通道。

# 第五阶段：反馈控制

之前是：

```text
ESP32 → 电机
```

现在升级成：

```text
       ┌─────────────────┐
       │                 ↓
目标 → 控制器 → 电机 → 实际速度
       ↑                 │
       └──── 编码器 ─────┘
```

这就是：

> **闭环控制**

---

## 实验 14：编码器

增量编码器通常有：

```text
A
B
```

两相信号：

```text
A ──┐ ┌──┐ ┌──
    └─┘  └─┘

B ────┐ ┌──┐
      └─┘
```

两个信号相位相差约 90°。

因此可以判断：

- 转了多少
- 转得多快
- 转动方向

这就是：

> **Quadrature Encoder**

---

## 实验 15：PID

例如：

```text
目标速度 = 100 RPM
实际速度 = 80 RPM
```

误差：

\[
e=100-80=20
\]

PID 控制：

\[
u=K_pe+K_i\int e\,dt+K_d\frac{de}{dt}
\]

输出控制 PWM。

系统表现：

```text
负载突然增加
       ↓
速度下降
       ↓
ESP32 检测到
       ↓
提高 PWM
       ↓
恢复到 100 RPM
```

这就是闭环控制真正的意义。

PID 是：

- 机器人
- 无人机
- 电源
- 工业控制
- 电机驱动

中的核心思想之一。

## 实验 16：IMU

可以使用：

- MPU6050
- ICM42688
- BMI270
- 其他 IMU

典型输出：

```text
Accel X
Accel Y
Accel Z

Gyro X
Gyro Y
Gyro Z
```

### 加速度计

特点：

```text
长期稳定
但运动时噪声和干扰比较大
```

### 陀螺仪

特点：

```text
短期响应很好
但积分后会漂移
```

所以需要：

```text
Accelerometer
       │
       ├──→ Sensor Fusion → Angle
       │
Gyroscope
```

建议先学：

> Complementary Filter

然后再理解：

> Kalman Filter

这就是滤波真正进入工程应用的例子。

```text
         IMU
          ↓

          ↓

          ↓
        Error
          ↓

          ↓
```

```text
恢复水平
```

- 舵机支架

## 实验 18：两块 ESP32

先用 UART：

```text
ESP32 A
   │
 UART
   │
ESP32 B
```

自己定义简单应用协议，例如：

```text
0xAA
Length
Command
Data
CRC
0x55
```

示例帧：

```text
AA 04 01 5A 23 9F 55
```

理解：

- 帧头
- 长度
- 命令
- Payload
- CRC
- 帧尾

然后把物理通信方式换成：

> ESP-NOW

你会发现，上层协议并不一定需要改变。

这会帮助理解：

> **通信介质和通信协议是不同层的问题。**


> **分布式机器人控制系统**

# 一句话总结

学习 ESP32 最有价值的方式不是：

> 点灯 → 接温湿度计 → 做个网页

而是：

> **用 ESP32 把电路、信号、通信、控制、无线、PCB 和机器人系统完整串起来。**

最终目标不是“会用 ESP32”，而是借 ESP32 建立完整的硬件系统认知。
